# v3 원시 SVO 품질 교정 재추출 프롬프트

당신은 1차 SVO 검수에서 endpoint 제약 제거 또는 열거 분리 위반이 발견된 법령 의미 단위를 처음부터 다시 추출한다. 반드시 JSON 객체만 반환한다.

우선순위는 다음과 같다.

1. `subject`와 `object`에는 관계의 핵심 엔티티인 짧은 명사구만 둔다. 사람·기관·문서·절차·처분·정보 등 핵심 명사는 남기되 그 대상을 선별하는 자격절·조건절·관형절은 제거한다.
2. 금액, 기간, 비율, 횟수, 범위, 촌수, 인원수, 연령, 직급·등급·급수는 전부 endpoint에서 제거한다.
   - `사원 1인` → `사원`
   - `3년 이상 재직한 경력이 있는 사람` → `사람`
   - `2년 이내에 수행한 업무` → 문맥상 업무명이 있으면 그 업무명, 없으면 관계를 만들지 않는다.
   - `500만원 이하의 과태료` → `과태료`
3. 법령·조문이 단지 뒤 명사를 한정하면 근거 부분을 제거한다.
   - `「민법」 제777조에 따른 친족` → `친족`
   - `「자본시장과 금융투자업에 관한 법률」에 따른 투자매매업자` → `투자매매업자`
   법령이나 조문 자체가 실제 행위 주체·대상이면 유지한다.
4. `사항`, `내용`, `대상`, `업무`, `행위`, `것`, `경우`, `각 호`를 단독 endpoint로 반환하지 않는다. `context_text`의 상위 행위와 `unit_text`의 구체 명사구를 결합할 수 있으면 구체 명사구를 사용하고, 구체 endpoint를 만들 수 없으면 해당 관계를 생략한다.
5. 주어·목적어 열거를 결합 문자열로 두지 않는다. `또는`, `및`, `와/과`, `ㆍ`, 쉼표가 실제로 여러 엔티티를 나열하면 공통 predicate를 적용한 별도 SVO로 나눈다.
6. predicate의 병렬 행위도 반드시 별도 SVO로 나누고 각 predicate를 완전한 표현으로 쓴다.
   - `심의ㆍ의결한다` → `심의한다`, `의결한다`
   - `서명 또는 날인한다` → `서명한다`, `날인한다`
   - `신설하거나 폐지한` → `신설한`, `폐지한`
7. 법령명·기관명·위원회명·정의된 용어·관용적으로 하나인 복합명사는 내부의 `및`, `과`, `ㆍ`만으로 분리하지 않는다.
8. `context_text`와 `unit_text`는 하나의 SVO 추출 단위다. 말단 호·목이면 상위 주어·술어와 말단의 구체 명사구를 결합한다. object를 `각 호`, `사항`, `업무`로 두지 않는다.
9. 관형절·내포절에도 명시적 행위자와 대상이 있으면 추출한다. 실제 주체를 같은 의미 단위에서 특정할 수 없으면 추측하지 않는다.
10. 조건·절차·허용 여부를 새 관계로 만들지 않는다. `공시하지 않아도 된다`는 관계를 만들지 않는다.
11. `unit_text`와 결합되지 않는 `context_text`만의 관계를 반복 추출하지 않는다.
12. alias 치환, 관계 타입 정규화, 법률 해석은 하지 않는다. 원문에서 확인되는 핵심 표현과 행위만 사용한다.

반환 형식:

```json
{
  "relations": [
    {
      "subject": "제약을 제거한 핵심 엔티티",
      "predicate": "분리된 완전한 원문 행위 표현",
      "object": "제약을 제거한 핵심 엔티티"
    }
  ]
}
```

관계가 없으면 `{"relations": []}`를 반환한다. 설명이나 추가 필드는 반환하지 않는다.
